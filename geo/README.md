# Геодвижок О!кно

Публичный адаптер: `geo.service.compute_hotel(hotel: dict, data_dir: Path, *, new_building: dict | None = None) -> {claims, geo}`. `data_dir` содержит `seed/` с реальными геослоями S1 и `geo/terrain_30m.npz`. Runtime использует только standard library, numpy, numba, shapely, pyproj и astral из общего lock. Сетевых вызовов нет. Расчёт пишет инспектируемые JSON и numeric NPZ в `data/geo`; каталог должен быть доступен на запись.

Базовый JSON имеет все поля Geo из контракта и `claims` для загрузки готовых claims без повторного расчёта. Промежуточный `geo_claims.jsonl.gz` объединяется загрузчиком seed с остальными claims. Это не альтернативный seed отелей. В NPZ нет object arrays: читать только `np.load(path, allow_pickle=False)`.

Воспроизведение из скачанных GeoTIFF (rasterio нужен только отдельному окружению пайплайна):

```sh
python -m pipeline.build_dsm path/to/N43E039.tif path/to/N43E040.tif --output data/geo/terrain_30m.npz
python -m pipeline.compute_views --data-dir data --output-dir data/geo --workers 4
python -m pipeline.compute_validate --data-dir data --geo-dir data/geo
pytest -q geo/tests
```

`build_dsm` преобразует Copernicus DSM в UTM37N, 30м, EGM2008, bilinear. Отсутствующие пиксели остаются NaN. Каждое здание ближней сетки 2м × 2,4км получает оценку основания по 10-му перцентилю DSM в 60м окрестности, исключая footprints всех зданий. Внутри footprint исходный пиксель крыши **заменяется** основанием плюс высота, высота OSM не прибавляется к крыше Copernicus. Это приближённая очистка DSM; деревья и остаточные размазанные крыши не исчезают полностью.

Фасады — реальные внешние рёбра полигона с внешними нормалями. Группируем их по восьми румбам, ставим наблюдателей на 1,5м снаружи, оставляем другие крылья собственного здания препятствиями. Луч начинается в 4м, сектор окна ±75°, азимутальный шаг 3°. Высота глаза: `base + (floor-1)*3 + 1.5`. При неизвестной этажности рассчитывается только условный первый уровень; вывод о номерах на верхних этажах остаётся unknown.

Луч идёт с шагом 2м до 1,2км, затем 30м до 30км. Высоты исправляются на кривизну Земли с коэффициентом `1-1/7`. Море — только после пересечения лучом реальной ориентированной материковой береговой линии OSM (земля слева), при DSM≤1м. Замкнутые полигоны островков и волноломов вычитаются как суша; кровля здания никогда не считается морской целью. Начальную сторону берега определяем в пределах 2км от картированного берега; за этим пределом `sea_view` unknown. Незагруженные острова и дальние изгибы береговой линии остаются ограничением. Морской вид требует угловой ширины ≥10°. Это угловая доля моря в горизонтальном секторе, не доля площади фотографии.

Горы — видимые клетки рельефа ≥200м на расстоянии ≥1,5км. Это геометрический хребет; название вершины не угадывается. Именованные вершины и достопримечательности с известной высотой проходят отдельный LOS и попадают в `landmarks`; если входных POI нет, список пуст. Для каждого месяца Astral даёт путь солнца 15-го числа с шагом 2мин; геометрический солнечный диск радиусом 0,27° сравнивается с профилем горизонта по этажам. Видимый закат требует ≥4мин видимости в последних 5° над геометрическим горизонтом. Облачность и переменная атмосферная рефракция не моделируются.

Monte Carlo: 64 прогона, seed=20261026. Изменяются высоты зданий, высота этажа, одна из распределённых точек фасада и общий коррелированный сдвиг DEM σ=2,4м. Height/levels имеют отдельные распределения; неизвестные высоты берутся из эмпирического распределения региона (при его отсутствии из явно заданного prior). Это чувствительность модели к допущениям, **не оценка реальной точности**. Confidence дополнительно уменьшается по покрытию высот зданий-блокеров; при их отсутствии — зданий на направленных наружу лучах. `nearby_height_coverage` хранится отдельно и не подменяет покрытие влияющих зданий. IDs блокеров и всех зависимостей сохраняются для актуализации.

Шум — некалиброванная приближённая модель **наружного** шума: источники дорог, действующих ж/д и потенциальных ночных баров; энергетическое сложение; затухание и экранирование геометрией зданий. Нет измеренных транспортных потоков/поездов/калибровки; диапазон ±8дБ — допущение модели. Это не шумоизоляция и не измерение. Известные дневные интервалы баров исключаются из ночной суммы; сложные opening_hours остаются unknown, полный OSM parser не имитируется.

Маршрут — Dijkstra по реальным направленным доступным рёбрам, без дорисовки связи между компонентами. Тоблер `6 exp(-3.5|grade+0.05|)` км/ч; уклон ограничен ±30%, лестницы ×2, paths/tracks ×1/0,6. Обратный путь считается независимо. Сохраняются node IDs, подъём в обе стороны, лестницы, пересечения с магистралями/ж/д и tunnel/bridge/crossing. Точки отеля/пляжа привязаны к ближайшему узлу в ограниченном радиусе, соединитель вне графа не подтверждён и явно ограничивает вывод. Высоты взяты из DSM, а не геодезии; короткие рёбра и подъём чувствительны к крышам и растительности. Если путь недоступен — `beach_walk` unknown, прямую линию маршрутом не выдаём.

Для `/changes`:

```python
from geo.changes import new_building_fixture
from geo.service import compute_hotel
baseline = compute_hotel(hotel, data_dir)
fixture = new_building_fixture(hotel, baseline['geo'])
after = compute_hotel(hotel, data_dir, new_building=fixture)
```

Fixture явно synthetic, это гипотетическое 16-этажное здание высотой 48м. Его полигон входит в локальный DSM; все LOS, солнечные и MC расчёты выполняются заново. Имена `*-change-<hash>.json/.npz` сохраняют baseline. Изменение может уменьшить угловую ширину вида, повысить минимальный этаж или не изменить доступность — результат не переключается заранее заданным bool. Все claims изменённого сценария помечены synthetic.

Для быстрого повторного сценария офлайн создаётся компактный numeric LOS-кэш. В поставке он подготовлен для `osm-node-10058556917` («Островок», зона B):

```sh
python -m pipeline.compute_runtime_cache --data-dir data --geo-dir data/geo --hotel-id osm-node-10058556917
```

Он хранит ближайшую видимую цель, максимальный её угловой наклон и профиль горизонта отдельно для каждого луча, этажа, наблюдателя и мира Monte Carlo. Runtime точно пересекает лучи с новым выпуклым полигоном, вычисляет угловой профиль его крыши с кривизной, сравнивает его с сохранёнными целями и пересчитывает ширину вида, пороги этажей, солнечные окна и вероятности. Это сокращает холодный сценарий до порядка 2с на рабочем ноутбуке; замер и реальные результаты лежат в `data/geo/change_demo.json`. Сверяются SHA baseline, кэша и исходных данных. Для отсутствующего/устаревшего кэша, далёкого или невыпуклого здания автоматически используется полный движок.

В компактном сценарии новые claims создаются только для моря, гор и заката. Шум и пеший граф сохраняются от baseline с явным ограничением: этот вариант `/changes` проверяет изменение вида. Тот же 64-мировый ансамбль описывает неопределённость существующих зданий; высота нового здания разыгрывается отдельным фиксированным seed=20261027. Точный полигон и 2м растеризация могут расходиться на несколько градусов по крайним лучам, что проверяется синтетическим тестом.

При изменении состава гостиничного портфеля готовые результаты объединяются без повторного расчёта незатронутых отелей:

```sh
python -m pipeline.compute_export --data-dir data --geo-dir data/geo --prune
python -m pipeline.compute_validate --data-dir data --geo-dir data/geo
```
