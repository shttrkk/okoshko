# Инженерные решения

## 2026-10-26 Ф0

1. **Сквозной сценарий — главный приоритет.** Blueprint §6 задаёт интеграционный smoke: поиск → карточка → вопрос → ответ → паспорт → изменение → студия. Ширину каталога сокращаем раньше глубины этого пути.
2. **Сочи, bbox из исследования источников.** `region_selection.md` пока отсутствует. Начальный bbox `[39.65,43.55,39.80,43.65]` (lon/lat), цель 150–250 объединённых объектов OSM/Overture. Фактическое число покажем после сбора, без искусственного добивания.
3. **Два сервиса, один origin.** FastAPI раздаёт API, SPA и PMTiles; Postgres 17/PostGIS 3.6. Redis/pgvector не добавляем: до 250 отелей детерминированное ранжирование и вектор характеристик помещаются в память.
4. **Claims append-only.** Pydantic проверяет wire-схемы, PostgreSQL дополнительно гарантирует NOT NULL provenance, непустое evidence, confidence и TTL. Обновление создаёт новый claim; facts материализуются Resolver.
5. **Типизированные JSONB-документы.** Данные храним как `id,payload` с generated SQL-полями и индексами для provenance/геометрии. Это единый формат COPY seed и REST-контрактов, сокращающий интеграционные расхождения. Миграции и контракты меняются только через точку интеграции.
6. **Известные закреплённые версии, lock с хэшами.** Python 3.12.10; JS собирается на BUILDPLATFORM, Python amd64 использует только binary wheels. Версии из исследований не принимаем без успешной установки и сборки. Local tooling: pip 24.0 + pip-tools 7.4.1 (новый pip несовместим с этой версией pip-tools).
7. **Данные не равны симуляции.** Реальные геоданные и расчёт отделены флагом от симулятора отельера, mock карточек, fixture новой постройки и тестовых метрик. Отсутствие исходных данных даёт unknown, а не генерацию.
8. **Геодопущения раскрываются.** Copernicus — DSM, двойной учёт крыш предотвращаем оценкой земли; модель шума не является инструментальным измерением. Не называем Monte Carlo эмпирической точностью.
9. **Без API ключа.** Offline по умолчанию, whitelist инструментов, правила русского языка и cache. Live OpenAI-compatible LLM — опция, сетевых запросов в boot нет.
10. **Параллельная разработка.** Независимые части (данные, георасчёты, API, интерфейс) разрабатываются в отдельных ветках со своей зоной файлов; общие контракты и слияние в main проходят одну точку интеграции.


11. **LLM transport:** Chat Completions для совместимости с произвольным провайдером; native JSON Schema → JSON mode → prompted и один bounded repair, все ответы проходят Pydantic. Общий бюджет запроса 2,4 с, ошибка провайдера возвращает deterministic fallback. Формат проверен по [official Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat) и [Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Live сеть не проверена без пользовательского ключа; transport tested MockTransport.

12. **Уточнение региона:** региональное исследование дописано после старта. Используем уточнённые зоны A `[39.690,43.555,39.790,43.635]` и B `[39.880,43.380,40.020,43.460]`. Финальный набор сначала250, включая60–80B, затем расширение к318 только при полном сквозном сценарии. 15/15 морских контрольных лучей не подменяют LOS от номера. Мини-расписание не выдумываем при отсутствии подтверждённого источника.

13. **Запускаемость и безопасность:** чистый клон с пустым build cache проверяем на каждой контрольной точке и после последнего коммита; startup читает только локальные seed. GitHub workflow только workflow_dispatch, локально make check + make audit. Известные Python advisories и npm production High/Critical блокируют готовность. Фактическое число отелей показываем из API, а не число318 из планового исследования.

14. **Первый dependency audit исправлен:** FastAPI0.162.0 + Starlette1.10.0, MapLibre6.16.0 и React Router7.18.4. Базовые образы обновлены до Python3.12.15 и Node22.23.4 (официальный Docker Hub tag inventory). Повторный pip-audit/npm audit production:0 advisories. Старые версии из Ф0 заменены после измеренного аудита, не исключениями.

15. **Подтверждение условий и синтетический demo seed:** confidence геомодели наружного шума остаётся0.38; оценки не поднимаем ради теста. В поставке есть три отдельные synthetic=true цитаты симулятора (Cascade SW/3, Приморская W/5, Brevis W/7, сентябрь), доступные в публичном ledger и видимые badge в выдаче. Это вымышленные ответы, не заявления реальных отелей. По требованию приёмки «✓ или ≈, confidence ≥ 0,6» группа all допускает только выполненное сравнение с confidence≥0.6; сам verdict при confidence<0.7 остаётся≈. Частичность из-за неизвестного веса питомца, общего заявления о виде, конфликтов или несовместимых scopes не засчитывается. Demo-check обязан проверять synthetic label и отдельно наличие реальных low-confidence noise facts.

16. **Компактное хранение:** логический URI GeoJSON и hash несжатых bytes сохраняем, физический файл gzip mtime0. Geo read helper и HTTP Content-Encoding обеспечивают совместимость без нового научного расчёта. Неиспользуемые дубли buildings/osm_features CSV удаляем; источником геометрии остаётся один GeoJSON gzip.

17. **Полный dependency gate:** make audit включает runtime/dev/pipeline Python locks, npm full и prod; scanner error или skipped dependency блокирует PASS. Исправлены 10 dev advisories обновлением pip26.2.2, setuptools84.2.1, pytest9.1.1 и совместимых инструментов; не suppress.

18. **Сдача.** Готовим проверенный коммит main и тег `submission` локально; push в репозиторий команды и настройки публичности выполняет владелец репозитория.

19. **Ограничения маршрута:** Criterion дополнен no_stairs/no_crossings(defaultfalse). Одна beach_walk описывает distance/time и дополнительные AND-ограничения маршрута; missing flags означаютunknown, не отсутствие лестниц. «Коляска» делает no_stairs=true, это видно пользователю. Боковойзакат подписываем по геометрии, не меняя ранее рассчитанные числа без новой версиигеоданных.

20. **Частичные POI наблюдения:** неизвестный въезд автомобиля не отменяет измеренное расстояние до парковки. Resolver сохраняет известные числовые расстояния car/family/pharmacy как computed, значение available остаётсяnull. Только сравнение известного поля может быть≈; available=null никогданестановится✓. local_poi_lookup@2 даёт confidence0.65 физическому расстоянию (тотжеприорOSMнаблюдений), неразрешениюуслуг. Архивныеclaims/dates не изменяются, manualrecollectсоздаётновуюзапись.

21. **Freshness без фиктивной свежести:** повтор георасчёта над теми же inputSHA не является новым наблюдением. Watcher сравнивает физические snapshots с evidence, сохраняет stale и исходныйvalid_until при неизменных данных; новый source hash разрешает пересчёт. Симулятор тоже не превращается в реальноеобновление.

22. **История сохраняется полностью.** Не выполняем squash, filter или orphan и не создаём новый корневой коммит ради размера: полная история важнее мягкой цели 150 МБ для Git pack. Отслеживаемые файлы не больше 50 МБ, полезные данные уже сжаты gzip/LZMA, исторические генерации сохраняются. Push выполняет владелец; ссылки добавляются при полной готовности.

23. **Чистый запуск.** Тестовый драйвер может использовать локальные QA-инструменты, но Compose запускается с PATH, содержащим только Docker CLI, плагины и credential helpers; Python и Node на хосте для запуска продукта не нужны. Отдельный прогон без `.env` фиксирует отсутствие файла явно. Зависимости браузерного прогона подключаются только после health и не являются ручным шагом запуска приложения.


24. **Недоверенный LLM вывод не имеет полномочий.** Предложение парсера не содержит source/confidence/identity/confirmed/dates; разрешены только поля характеристики и проверяемые цитаты. Server principal задаёт hotel scope и synthetic; demo accounts всегда synthetic. Bearer нужен для private writes/cabinet; HttpOnly SameSite=Strict cookie с Path=/api/runs обслуживает только чтение SSE. Production SSO и отзыв гостевых capability — отдельная работа, не заявленная готовность.

25. **Сравнение с фильтрами — модельная метрика.** Базовый фильтр — расстояние точки отеля до OSM coastline ≤500 м; основной — совместимые facade/floor/month море+закат, confidence≥0,6, сентябрь. Unknown не считается отрицательным. 20 кандидатов вне радиуса — дополнительное модельное покрытие, а не измеренный рост продаж или проверка каждого окна.

26. **Покрытие считает только исполняемый продуктовый Python.** pytest-cov исключает backend/tests и geo/tests. Отчёт сохраняет все остальные backend/geo модули, включая слабее покрытые views/walk, без искусственного порога сдачи. Runtime зависимости не расширяются: plugin только в dev lock.


27. **Повтор демо сохраняет историю.** Полный сценарий с новым домом меняет факты и законно снижает число совпадений Маши с 3 до 2. Для исходного сценария используется отдельный локальный Compose project `okno-demo` (настройка только в ignored .env); прежний `okno` и его volumes сохранены. Claims/events/passports не удаляются и не переписываются ради приёмки. Чистый клон начинает собственную исходную БД, поэтому baseline demo-check запускается до изменений или в изолированном проекте.

28. **Языковые метрики разделены.** Авторский development, исходный holdout и дополнительный независимо написанный корпус публикуются отдельно. Эталоны заморожены до настройки; первый результат сохраняется. Совпадение с authored gold не называется точностью гостиничных фактов или произвольной речи.

29. **Неизвестное обязательное условие сохраняет силу.** Regional coverage переносит его в no_data, отдельно хранит исходный hard и включает его в must_total. Оно запрещает полное совпадение. Значение поля available не устанавливает наличие другого поля, например скорости Wi-Fi. Применение редактора восстанавливает смысл приоритетов и удалённых условий.

30. **Локальная LLM включается по результатам измерения.** Продуктовый QueryUnderstanding имеет общий бюджет 2,2 с. qwen2.5:3b на локальной машине не показала выигрыша при этом бюджете: 232 из 236 обращений завершились fallback по времени. По умолчанию остаётся offline; веса находятся только вне репозитория и образа. Контроль Docker bridge не считается полной оценкой модели.

31. **Дополнительные солнечные признаки — отдельные прокси.** Используются сохранённые NPZ-профили горизонта и астрономия для 15-го числа месяца, без нового Monte Carlo. Confidence ограничена 0,54. Ближайший контур с уровнями не устанавливает этажность отеля; условность записывается в evidence, пограничный contains отбрасывается. В интерфейсе неизвестная Hotel.floors позволяет только один условный уровень просмотра.

32. **Изменение геометрии инвалидирует зависимые признаки.** Старые значения утреннего/вечернего солнца и железнодорожного шума не переносятся на новый дом. Для другого именованного варианта создаётся unknown с supersedes и evidence события; сохранённые расчёты самого варианта не удаляются. Повторный tool run проверяет версию метода, SHA входов и актуальный artifact.

35. **Объекты на карте связаны с конкретным фактом.** Пляж, аптека, парковка, площадка и парк получают координаты только по точному OSM ID актуального факта. Для полигона показывается подписанная точка геометрии, а не выдуманный вход. Геометрия региона и внутренний building_index не входят в API карты; отсутствие связи не заменяется ближайшим объектом.

36. **Сообщение о Wi-Fi не заменяет измерение связи.** 24 тега OSM сохраняются как сведения конкретного объекта с confidence 0,55. В интерфейсе они подписаны как непроверенное наличие услуги; отсутствие измеренных скоростей остаётся неизвестным и не позволяет выполнить обязательное условие работы. Пересборка компактного среза отделена от сетевого сбора региона.

37. **Открытые экраны обновляются по изменению данных.** Один watcher на видимую вкладку проверяет компактный process-local revision и сохраняет прежние данные до готовности нового ответа. Записи telemetry не вызывают refetch, скрытые вкладки не опрашивают сервер. Instance меняется после перезапуска процесса; распределённый event bus для прототипа не вводится.

38. **Срез вопроса — пожелание, не подтверждение номера.** Одна очередь сохраняет до восьми различных сторон/этажей/месяцев по свойству, повторный запрос не создаёт дубль. Отельер видит исходный модельный срез; AnswerParser извлекает область только из дословного ответа. Простое «да» при уточнении среза требует подробностей; несколько месяцев или неподдерживаемый период не превращаются в утверждение на весь год.

39. **Метрики привязаны к входам и методике.** Parser report проверяет SHA исходников, каталога, корпусов и имён отелей; stale-числа не показываются. Критерии и полный разбор считаются отдельно. Слабый nDCG описывает согласие с замороженными правилами и показывает judged coverage/bounds; он не подменяет независимую оценку гостей. Причины «Почему не выше» используют только серверные сравнения.

40. **Зависимые характеристики получают версию входов.** Копия геосвойства и составное выражение не переживают изменение реального входного значения как действующий факт. Неизменяемые canonical claims несут versioned список retired IDs; Resolver исключает их при повторной материализации и показывает explicit unknown с причиной. Для произвольного value_schema не создаётся невалидное значение Claim; повторный расчёт может вернуть computed. Механизм относится к apply_change и объявленным зависимостям Registry, а не произвольным SQL-записям.

41. **Неверная идентичность важнее красивого score.** Отдельная проверяемая политика временно скрывает пляжную карточку, городскую точку и запись отеля с неверной геопривязкой. Сохраняются raw seeds, claims, старые labels и полная история; исходные доказательства доступны по ссылке. Три выявленных случая не дают оценки общей ошибки каталога. Неоднозначные имена, одинаковый сайт или отсутствие этажности сами по себе не исключают объект.

42. **Модель и сообщение источника не подменяют друг друга.** Вероятность Geo отображается только для факта с собственной модельной probability. Boolean-ответ о виде или тишине сохраняет своё основание и не получает выдуманные проценты/дБ. При неизвестной этажности геомодалка ограничивается условным уровнем; ввод вне диапазона ограничивается в состоянии. «Закат сбоку» определяется по точной нормали evidence или единственной нормали Geo, а не по центру условного компасного сектора.

43. **Отсутствующий расчёт не означает безопасный маршрут.** У семейного POI-факта переходы остаются unknown. Предварительная проверка железнодорожного шума использует те же положения фасадных наблюдателей и функцию источников, что полный расчёт; только доказанное отсутствие источников позволяет пропустить загрузку модели региона.

44. **Число получает размерность из явного условия.** Соседний порог Мбит/с связывается только с однозначным запросом связи; промежуточное другое желание блокирует перенос. Наличие Wi-Fi без требования скорости проверяется отдельным полем, не создаёт измеренные Мбит/с и при confidence 0,55 не выполняет must как надёжное подтверждение. Повествовательное упоминание места не становится пожеланием.

45. **Приёмка и метрики используют действующие ограничения.** Проверка чистого клона подключает host QA-инструменты только после готовности Docker-продукта; затем выполняет make check и браузер. Сравнение с береговым фильтром передаёт в evaluator известный диапазон этажей и исключает held-объекты; исходные 250 записей не переписываются.

46. **Соединения ограничены, транзакции не повторяются.** Repository переиспользует до четырёх соединений с pre_ping и трёхсекундным ожиданием. Каждый lease имеет собственный commit/rollback; сомнительное соединение удаляется. При потере ответа после commit данные не публикуются из памяти и не записываются повторно: снимок и кэш сбрасываются для чтения фактического состояния БД. Возврат lease предшествует ожиданию search lock, чтобы не создать взаимную блокировку.

47. **Расширение словаря проверяется на действиях и отрицаниях.** Просьба создать фото не становится требованием фотогалереи, а аренда номера с фото сохраняет свойство. Явная температура задаёт приоритет вместо неявного порога активности; внутреннее отрицание затемнения сохраняется. Неверные старые labels и владение машиной не используются для искусственного повышения score. Авторский набор и независимая от реализации выборка показываются отдельно.

48. **Групповой поиск описывает положения, не номерной фонд.** RoomScope — отдельный контракт пожелания с необязательным фасадом и ограничением floor_max; Scope доказательств не ослабляется. Общие условия проверяются один раз, персональные — независимо в одном отеле. Число людей не даёт количество комнат, одинаковое положение не доказывает несколько свободных номеров. Утвердительная фраза описания требует fact_ids; unknown и синтетика обозначаются отдельно.

49. **Описание положения покрывает весь диапазон.** Профиль разбивает этажи на непрерывные интервалы по фактам; неизвестный участок не становится положительным обобщением. Фразы хранят fact_ids и evidence_refs, полные доказательства догружаются отдельно. Для неизвестной этажности остаётся условный уровень 1. Наличие типа, количества номеров, соседства и кроватей не выводится из геометрии.

50. **План рекомендует проверенный контекст.** Ранжирование выбирает доказанный этаж и сторону, не растягивает положительный исход на весь диапазон источника с внутренними отрицательными срезами. Для солнечных свойств требуется покрытие выбранного месяца. Неразобранное личное пожелание препятствует полному совпадению. Одинаковые запросы внутри одной оценки отеля переиспользуют расчёт, но получают независимые копии плана и подписи.

51. **Совет хранит доказательства каждой стороны.** Советы для гостя агрегируют согласованные диапазоны до применения лимита. Каждая option содержит исходный scope и fact_ids; текст не превращает несколько сторон в один номер. Короткое описание остаётся детерминированным, подробности и ограничения доступны отдельно.

52. **Фотография не заменяет доказательство характеристики.** Обложки здания, уличный кадр и интерьер номера имеют разные типы и атрибуцию. Интерьер не связывается со стороной, этажом и видом. Принятые фотографии проходят визуальную проверку; официальные изображения остаются ссылками с домена сайта, уличные — лицензированными локальными миниатюрами. При отсутствии исходных данных сохраняются схема и внешняя ссылка, а не подставное фото.

53. **Происхождение не заменяется уверенностью.** Реальный ответ отеля, расчёт и демонстрационный ответ имеют разные подписи. Confidence не превращает расчётное значение или симулированный ответ в подтверждение отеля. Отображаемое имя хранится в каталоге отдельно от прежних названий разбора. Прямое «не знаю» закрывает вопрос без утверждения о характеристике.


54. **Публичный журнал не раскрывает запрос гостя.** Список, детали и поток шагов поиска проходят одну проекцию с разрешёнными полями; авторизация служебной страницы не снимает это ограничение. Сохранённая трасса не переписывается, закрытые интервью остаются под проверкой доступа.

55. **Частичный ответ не превращается в общее обещание.** Неизвестные сезонные ограничения сохраняются как уточнение; для разных групп номеров сохраняются отдельные условия без переноса на весь отель. «Не знаю» закрывает вопрос без claim. Демо-доступ к кабинету и происхождение введённого ответа — разные признаки. Исправление создаёт новый ответ; согласованный ранее паспорт автоматически не переписывается.


56. **Имя интерфейса не меняет frozen-разметку.** Совместимость старого ranking-набора с display_name доказывается совпадением исходных байтов после удаления единственной добавленной строки. Условия, факты, пороги и labels остаются замороженными; исключение не распространяется на другие поля или файлы.

57. **Знаменатель соответствует выполненной проверке.** Пробный прогон Студии проверяет до трёх отелей и показывает их имена. Размер каталога и размер выборки выводятся раздельно; отрицание и неизвестное нельзя выводить из отсутствия уверенного совпадения. Полный подсчёт нового признака остаётся задачей опубликованного backfill.

58. **Адрес по содержащему контуру, без догадки о соседях.** Офлайн-дополнение использует тот же снимок OSM для улицы и дома и отдельно сохранённые административные полигоны для района. Исходные конкретные адреса сохраняются. Уточнение допускается только при согласовании идентификатора, координат и исходного адреса. Валидация и геометрия выполняются до короткой транзакции; запись сравнивает весь ожидаемый payload. Ручное или конкурентное изменение не перезаписывается, параметры доверия источника при повторной загрузке сохраняются.

59. **Цель вида отделена от положения номера.** Видимость разных достопримечательностей хранится с отдельным `Scope.landmark_id`: положительный вид на один объект не спорит с отрицательным видом на другой. Критерий может выбрать конкретную цель, а сторона и этаж по-прежнему задают положение номера. У прежних срезов отсутствующий идентификатор не сериализуется: их wire shape, ключи и замороженные ranking inputs остаются прежними. Неизвестная высота объекта запрещает утверждение о его видимости.

### 60. Загрузка дополнительных наблюдений и карта целей (27.10.2026)

Дополнительные открытые данные подключаются отдельным проверяемым набором. Целостность и ссылки проверяются до короткой транзакции вставки, исходные сиды и действия пользователей сохраняются. Собственные доказательства новых полей маршрутов и климата не объединяются с надёжностью старых полей. Вид на разные объекты различается через scope.landmark_id. На карте выводятся только реально сохранённые лучи для выбранного этажа; после изменения геометрии старые лучи скрываются до пересчёта. Контур Фишта без подтверждённой высоты не позволяет вычислить видимость.

Гостевой риск допускается только при расстоянии от реального фасада до 150 м, секторе ±60° и явной construction-specific проверке/обследовании не старше 90 дней; срок перепроверки 14 дней. ### 67. Доступность маршрута и версия проверки намерения (28.10.2026)

### 68. Короткий текст не меняет доказательство (28.10.2026)

Это описание исторических средних, не прогноз. Исходные числа, метод, период и ограничения доступны в подробностях. Будущая перепроверка паспорта нейтральна; подтверждение, расчёт и демо-ответ имеют разные подписи.

### 69. Происхождение сохраняется в компактном ответе (28.10.2026)
