# О!кно: runbook

## Запуск для жюри

Из корня клона репозитория:

```sh
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8080. `/health` возвращает `{"status":"ok"}`. Миграции, seed и подготовка поискового снимка выполняются автоматически. Интернет нужен для публичных образов и зависимостей при первой сборке; само демо работает офлайн. Ключ LLM не требуется.

В поставке 250 отелей Сочи: 175 в центре и 75 в Адлере–Имеретинке, 16 базовых спецификаций, 20 340 географических claims и 3 364 открытых наблюдения климата, воздуха и Commons. При первом старте локально добавляются 750 наблюдений о ближайших POI. Ответы о тишине и питомцах явно синтетические: три ответа о тишине, семь завершённых диалогов и два вопроса для прохождения в кабинете. Путь проверки за пять минут — в README.

Тестовый вход: `hotelier / hotelier123`. Бронь демонстрационная, без оплаты; уведомления остаются в приложении.

## Разработка и проверки

Для локальных команд Python:

```sh
python3.12 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements-dev.lock
```

Frontend: `cd frontend`, `npm ci`, `npm run dev`. Интерфейс разработки доступен на http://localhost:5173, запросы API идут к приложению на 8080. В Docker интерфейс и API доступны вместе на 8080.

| Команда | Назначение |
|---|---|
| `make up` / `make down` | Запустить Compose в фоне / остановить без удаления данных |
| `make seed` | Идемпотентно добавить seed; существующие ответы и паспорта не перезаписываются |
| `make pipeline` | Отдельно собрать открытые данные и пересчитать географические характеристики |
| `make eval` | Пересчитать отчёт по сохранённым данным и слабым меткам |
| `make test` / `make lint` | Тесты / Python и frontend lint |
| `make demo-check` | Приёмка Маши, пяти персон, доказательств и synthetic provenance |
| `make smoke` | Проверка работающего стенда и затем demo-check |
| `make audit` | Четыре Python и три npm скана зависимостей |
| `make check` | Lint, тесты, аудит и smoke уже запущенного Compose |
| `make demo-video` | Записать скринкаст по сценарию |

Миграции запускает `backend.boot` при старте контейнера. Не запускайте `python -m backend.boot` внутри уже работающего app: он попытается поднять второй HTTP-сервер. Для повторной загрузки данных используйте `make seed`.

После изменений: `make lint`, `make test`, `docker compose up --build -d`, `make smoke`. Проверяйте отсутствие файлов больше 50 МБ, tracked `.env` и реальных токенов в diff и истории. Все зафиксированные результаты и открытые пункты ведутся в `docs/STATUS.md`; перед сдачей перечитайте `docs/reviews/REVIEW_*.md`.

Контрольная точка 26.10.2026: полный pytest — 308 тестов и 125 subtests, lint и сборка интерфейса прошли; аудит четырёх Python и трёх npm наборов — 0 известных уязвимостей, ошибок сканера нет. Образ `linux/amd64` занимает 315 513 186 байт (около 301 MiB). Старт с пустой БД и готовым образом проверен за 46 с. Проверка чистого клона с пустым build cache ещё выполняется; цель ≤10 минут не отмечается выполненной до замера.

## Данные

Исходники загружаются в исключённую из Git директорию `data/raw/`. Сборка приложения не запускает pipeline. Лицензии, даты и SHA-256 открытых выгрузок находятся в `data/seed/manifest.json`, `data/seed/sources.json` и на `/sources`. Контракты seed — в `docs/CONTRACTS.md` §3, сценарии и ограничения синтетических данных — в `docs/internal/DEMO_FIXTURES.md`. Реальные фото сопровождаются лицензиями конкретных файлов. OTA не используются.

40 слабых меток сайтов относятся к 40 объектам, четыре метки парковки ограничены по смыслу. Независимых ручных меток нет; nDCG и полевая точность не измерены. Синтетические сценарии не считаются реальным покрытием или подтверждениями гостиниц.

## Диагностика

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 db
curl -f http://localhost:8080/health
```

Не удаляйте volumes при обычной остановке: там находятся ответы, паспорта и результаты пересчётов. Для намеренного полного сброса демо используйте `docker compose down -v`; все локальные изменения будут потеряны.

При поездке позже срока действия доказательств паспорт показывает необходимость перепроверки. Подтверждение номера не превращает текущие данные в гарантию будущих условий. Сначала проверьте даты поездки, срок доказательств, ограничения фасада и этажа, а затем таймлайн паспорта.

## Видео и сдача

Для записи нужны Node.js 22+, Chrome/Chromium и системные `ffmpeg`/`ffprobe`. Зависимости записи закреплены в `demo/package-lock.json`; `make demo-video` устанавливает npm-зависимости и Chromium, затем запускает сценарий. Подробности и параметры — в `demo/SCRIPT.md`.

Скринкаст готов: около 3 минут (178,9 с), 1920×1080, 30 кадров/с, около 10 МБ. Пройдены 11 сцен без ошибок, заполнение новой характеристики завершено для всех 250 отелей. Локальный файл `demo/okno-demo.mp4` не коммитится. Владелец должен предоставить публичную ссылку для README; доступ к ней проверяется в инкогнито.

Перед финальным тегом нужен чистый клон и пустой кэш сборки: замерить `docker compose up --build`, пройти smoke и ручной сценарий. Фактическое время, размер образа, SHA и результаты записать в STATUS и README. Не подменять этот замер стартом с готовым образом или существующей БД.

Текущий origin: `https://github.com/shttrkk/okoshko.git` — личный репозиторий, не адрес сдачи по правилам. URL команды в `ostrovok-hackathon-2026` указывает владелец. Тег `submission` ставится на последний коммит main после финального прогона. Push main и тега выполняет только владелец самостоятельно; оркестратор не вызывает `git push` и не меняет публичность репозитория. После отправки владелец сверяет удалённые SHA main и submission с проверенным локальным коммитом. Сдача не считается выполненной до проверки удалённого тега и публичной ссылки на видео.
