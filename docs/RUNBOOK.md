# О!кно: runbook

## Локальный запуск

Из корня клона репозитория:

```sh
docker compose up --build
```

Открыть http://localhost:8080. `/health` возвращает `{"status":"ok"}`. Миграции, seed и подготовка поискового снимка выполняются автоматически. Интернет нужен для публичных образов и зависимостей при первой сборке; само демо работает офлайн. Ключ LLM и файл `.env` не требуются. Для изменения дефолтов можно скопировать `.env.example` в `.env`.

Поставка содержит 250 исходных записей Сочи (175+75), 23 YAML-характеристики, географические и открытые реестры, дополнительный ledger шести traits и 24 OSM-наблюдения наличия интернет-услуги без измеренной скорости. Eligibility policy оставляет 247 доступных кандидатов, три прямых карточки показывают review. Локальный bootstrap использует сохранённые данные без сети. Три ответа о тишине, семь завершённых pets-диалогов и два подготовленных вопроса явно synthetic; это не реальные ответы гостиниц.

Публичные demo-аккаунты: `hotelier / hotelier123` — `demo_admin` для всех отелей; `cascade / cascade-demo-2026` — только Cascade (`osm-node-11866202895`); `brevis / brevis-demo-2026` — только Brevis (`osm-way-201474330`). Все создаваемые ими ответы принудительно synthetic, независимо от переданного флага. Это демонстрация scope/RBAC, не реальные аккаунты гостиниц. Бронь демонстрационная, без оплаты; уведомления остаются в приложении.

Login: `POST /api/hotelier/login`, тело `{username,password}`, ответ `{token,username,synthetic:true,role,hotel_ids}`. Кабинет, ответы/подтверждения и список/действия паспортов требуют Bearer и разрешённый hotel scope. `POST /api/changes/simulate` и `/refresh` требуют Bearer роли `demo_admin`. Без входа `GET /api/changes` не раскрывает индивидуальных уведомлений, только их количество в `payload.notification_count`. Для interview list/detail/SSE доступ ограничен scope; same-origin EventSource использует HttpOnly cookie с Path `/api/runs`.

`POST /api/hotelier/logout` удаляет SSE cookie, UI удаляет свой Bearer. Скопированный токен остаётся действителен до 12-часового expiry или перезапуска приложения; серверного отзыва отдельной сессии нет. UUID паспорта остаётся гостевой read capability без срока/отзыва. Studio/collect/quality demo-операции пока публичны. Полная таблица границ и ограничений — в [SECURITY](SECURITY.md).

## Повтор демонстрации

Сценарий «новый дом» меняет факты и может уменьшить число совпадений. Baseline `make demo-check` проверяет исходный seed, поэтому после изменения нужен отдельный чистый demo-проект. История предыдущего проекта сохраняется:

```sh
docker compose stop
export COMPOSE_PROJECT_NAME=okno-demo-repeat
docker compose up --build
```

Имя нового проекта должно ещё не использоваться. Переменная действует в текущем терминале; для следующих команд этого проекта используйте то же имя. Локальный стенд подготовки сейчас использует `okno-demo` через ignored `.env`; прежний `okno` остановлен, его volumes сохранены. В чистом клоне без `.env` Compose использует штатное имя `okno`. Удаление claims или переписывание истории для восстановления совпадений не требуется.

## Разработка и проверки

Для локальных команд Python:

```sh
python3.12 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements-dev.lock
```

Frontend: `cd frontend`, `npm ci`, `npm run dev`. Интерфейс разработки доступен на http://localhost:5173, запросы API идут к приложению на 8080. В Docker интерфейс и API доступны вместе на 8080.

| Команда | Назначение |
|---|---|
| `make up` / `make down` | Запустить Compose в фоне / остановить без удаления данных |
| `make seed` | Идемпотентно добавить seed; существующие ответы и паспорта не перезаписываются |
| `make pipeline` | Отдельно собрать открытые данные и пересчитать географические характеристики |
| `make eval` | Пересчитать отчёт по сохранённым данным и слабым меткам |
| `make test` / `make lint` | Тесты / Python и frontend lint |
| `make coverage` | Тесты с покрытием backend/geo, JSON в `docs/checks/coverage.json` |
| `make demo-check` | Приёмка Маши, пяти персон, доказательств и synthetic provenance |
| `make smoke` | Проверка работающего стенда и затем demo-check |
| `make audit` | Четыре Python и три npm скана зависимостей |
| `make check` | Lint, тесты, аудит и smoke уже запущенного Compose |
| `make demo-video` | Записать скринкаст по сценарию |
| `make demo-voice VOICE=/path/to/voice.wav` | Добавить голос владельца в отдельный MP4 без перекодирования видео |

Миграции запускает `backend.boot` при старте контейнера. Не запускайте `python -m backend.boot` внутри уже работающего app: он попытается поднять второй HTTP-сервер. Для повторной загрузки данных используйте `make seed`.

После изменений: `make lint`, `make test`, `docker compose up --build -d`, `make smoke`. Проверяйте отсутствие файлов больше 50 МБ, tracked `.env` и реальных токенов в diff и истории. Все зафиксированные результаты и открытые пункты ведутся в `docs/STATUS.md`; перед сдачей сверяйте их с отчётами `docs/checks/` и аудитом `docs/audits/summary.json`.

## Данные

Исходники загружаются в исключённую из Git директорию `data/raw/`. Сборка приложения не запускает pipeline. Лицензии, даты и SHA-256 открытых выгрузок находятся в `data/seed/manifest.json`, `data/seed/sources.json` и на `/sources`. Контракты seed — в `docs/CONTRACTS.md` §3, сценарии и ограничения синтетических данных — в `docs/internal/DEMO_FIXTURES.md`. Реальные фото сопровождаются лицензиями конкретных файлов. OTA не используются.

40 слабых меток сайтов относятся к 40 объектам, четыре метки парковки ограничены по смыслу. Независимых ручных меток нет; Независимая релевантность и полевая точность не измерены; `make ranking-eval` отдельно считает agreement со слабыми правилами, `make parser-eval` — authored intent cases. Синтетические сценарии не считаются реальным покрытием или подтверждениями гостиниц.

Сбор сайтов — отдельный разовый этап подготовки с robots.txt и запретом OTA. Runtime читает сохранённые фрагменты, сетевого website fetch нет. `python -m scripts.compare_filters` воспроизводит модельное сравнение с береговым фильтром; результат `data/eval/filter_baseline.json` и методику нужно читать вместе. Поле `provenance` в `GET /api/quality` использует единицу materialized facts, а не отели; mixed входит в synthetic, неизвестные/устаревшие/спорные значения исключены из знаменателя доли. Текущие seed-счётчики и методика — `data/eval/results.json`; runtime-only POI и действия пользователей считаются отдельно.

## Диагностика

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 db
curl -f http://localhost:8080/health
```

Не удаляйте volumes при обычной остановке: там находятся ответы, паспорта и результаты пересчётов. Для намеренного полного сброса демо используйте `docker compose down -v`; все локальные изменения будут потеряны.

При поездке позже срока действия доказательств паспорт показывает необходимость перепроверки. Подтверждение номера не превращает текущие данные в гарантию будущих условий. Сначала проверьте даты поездки, срок доказательств, ограничения фасада и этажа, а затем таймлайн паспорта.

## Приёмка чистого клона

Команда временно освобождает порт 8080 и после проверки возвращает текущий app. Для сборки в клоне нет `.env`, host Python/Node исключаются из PATH; QA-зависимости подключаются только после `/health`. Build cache очищается явно, используются новый Compose-проект и пустые volumes:

```sh
.venv/bin/python scripts/clean_clone_check.py --clone ../okno-clean-final --report docs/checks/clean_clone_final.json --prune --stop-current-app --without-env --docker-only-path --check --browser
```

`--check` выполняет lint, pytest, четыре Python и три npm audit scopes, API smoke и demo-check; `--browser` проходит реальный UI без записи видео и browser smoke. Новый clone destination должен отсутствовать. Сборка, health и полный QA фиксируются раздельно. При обычной остановке volumes сохраняются.

Для повторения счётчиков шести основных характеристик без изменения БД:

```sh
docker compose exec -T app python < scripts/measure_six_coverage.py
```

## Компания и описания положений

`make group-parser-eval` оценивает авторские групповые запросы и ловушки. `GET /api/hotels/{id}/rooms?month=9` возвращает компактные описания положений с fact_ids; полное доказательство догружается существующим маршрутом `/facts/{id}/evidence`. Число людей не задаёт количество номеров. Ограничения номерного фонда описаны в [GROUP_BOOKING](GROUP_BOOKING.md).

Все браузерные проверки (системный Chrome):

```sh
for task_smoke in frontend/scripts/*-smoke.mjs; do
  OKNO_BASE_URL=http://localhost:8080 \
  OKNO_BROWSER_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  node "$task_smoke" || exit 1
done
```

Проверка отдельного чистого клона без `.env`, с временной остановкой приложения `okno-demo` и сохранением его томов:

```sh
.venv/bin/python scripts/clean_clone_check.py \
  --clone ../okno-clean-company \
  --report docs/checks/company_clean_clone.json \
  --without-env --docker-only-path --check --all-smokes \
  --stop-current-app --current-project okno-demo --cleanup
```

`--all-smokes` не записывает видео. `--cleanup` удаляет только созданный проверкой уникальный compose-проект вместе с его томами и клоном. `--prune` дополнительно очищает build cache перед измерением. Проверочные Python/Node-зависимости подключаются только после готовности Docker-продукта.

## Дополнительные сведения о Сочи

Готовые `tz_*` данные загружаются без сети и ключей при штатном старте. `make tz-pipeline` собирает отдельный закреплённый образ и печатает план dry-run. Только явное `TZ_PIPELINE_ARGS='--stage all'` исполняет дополнительные стадии; полный базовый pipeline не вызывается. Точная дата PBF, проверенные источники, SHA и полевая неопределённость описаны в `data/seed/tz_manifest.json` и [TZ_COVERAGE](TZ_COVERAGE.md).

Приёмка: `make demo-check` включает 18 сценариев с дополнительными сведениями региона. Для отдельного стенда передавайте `OKNO_URL` и `OKNO_BASE_URL`; браузерные проверки блокируют Яндекс и Mapillary. `scripts/tz_metrics.py --url http://localhost:8081 --output /tmp/tz-metrics.json` измеряет все доступные компактные карточки и 40 тёплых поисков; это последовательный замер, не SLA под нагрузкой. `scripts/clean_clone_check.py --port 8081 --without-env` использует временный Compose override вне клона и не занимает 8080. Наличие пустого build cache и все дополнительные проверки задаются явными флагами этой команды.

## Приёмка ответов отеля на отдельной копии

Все `frontend/scripts/*-smoke.mjs` запускаются последовательно с `OKNO_BASE_URL=http://localhost:8081` и системным Chrome. Полный сценарий ввода, исправления ответа, Wi-Fi, будущего паспорта, компании и публикации Студии включается отдельно:

```sh
OKNO_BASE_URL=http://localhost:8081 OKNO_PANEL_R3_WRITES=1 \
  node frontend/scripts/panel-live-smoke.mjs
```

Режим с записью разрешён только на одноразовой локальной копии на 8081. Helper проверяет адрес перед каждым запросом; рабочий 8080 запрещён. Проверка медленной сети явно помечена как подмена: её API-запросы вообще не отправляются серверу. Остальные сценарии проверяют настоящие API и отдельно сохраняют отчёты и снимки в runtime/panel-live. Полное фоновое заполнение 250 отелей может занять несколько минут; интерфейс показывает прогресс, тест требует его продолжения и завершения.

При обычном обновлении `okno-demo` используйте `docker compose -p okno-demo up --build -d` без удаления томов. Проверки с созданием вопросов, ответов, паспортов и характеристик проводите на отдельной копии. Для чистого запуска на 8081 сначала освободите только порт проверочного проекта; `--without-env --check --all-smokes --cleanup` создают новый проект и удаляют только его. `OKNO_PANEL_R3_WRITES=1` включает дополнительные сценарии кабинета внутри этой приёмки.
