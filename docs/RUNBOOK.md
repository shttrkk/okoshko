# О!кно: runbook

## Локальный запуск

Из корня клона репозитория:

```sh
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8080. `/health` возвращает `{"status":"ok"}`. Миграции, seed и подготовка поискового снимка выполняются автоматически. Интернет нужен для публичных образов и зависимостей при первой сборке; само демо работает офлайн. Ключ LLM не требуется.

В поставке 250 отелей Сочи: 175 в центре и 75 в Адлере–Имеретинке, 16 базовых спецификаций, 20 340 географических claims и 3 364 открытых наблюдения климата, воздуха и Commons. При первом старте локально добавляются 750 наблюдений о ближайших POI. Ответы о тишине и питомцах явно синтетические: три ответа о тишине, семь завершённых диалогов и два вопроса для прохождения в кабинете. Путь проверки за пять минут — в README.

Публичные demo-аккаунты: `hotelier / hotelier123` — `demo_admin` для всех отелей; `cascade / cascade-demo-2026` — только Cascade (`osm-node-11866202895`); `brevis / brevis-demo-2026` — только Brevis (`osm-way-201474330`). Все создаваемые ими ответы принудительно synthetic, независимо от переданного флага. Это демонстрация scope/RBAC, не реальные аккаунты гостиниц. Бронь демонстрационная, без оплаты; уведомления остаются в приложении.

Login: `POST /api/hotelier/login`, тело `{username,password}`, ответ `{token,username,synthetic:true,role,hotel_ids}`. Кабинет, ответы/подтверждения и список/действия паспортов требуют Bearer и разрешённый hotel scope. `POST /api/changes/simulate` и `/refresh` требуют Bearer роли `demo_admin`. Без входа `GET /api/changes` не раскрывает индивидуальных уведомлений, только их количество в `payload.notification_count`. Для interview list/detail/SSE доступ ограничен scope; same-origin EventSource использует HttpOnly cookie с Path `/api/runs`.

`POST /api/hotelier/logout` удаляет SSE cookie, UI удаляет свой Bearer. Скопированный токен остаётся действителен до 12-часового expiry или перезапуска приложения; серверного отзыва отдельной сессии нет. UUID паспорта остаётся гостевой read capability без срока/отзыва. Studio/collect/quality demo-операции пока публичны. Полная таблица границ и ограничений — в [SECURITY](SECURITY.md).

## Разработка и проверки

Для локальных команд Python:

```sh
python3.12 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements-dev.lock
```

Frontend: `cd frontend`, `npm ci`, `npm run dev`. Интерфейс разработки доступен на http://localhost:5173, запросы API идут к приложению на 8080. В Docker интерфейс и API доступны вместе на 8080.

| Команда | Назначение |
|---|---|
| `make up` / `make down` | Запустить Compose в фоне / остановить без удаления данных |
| `make seed` | Идемпотентно добавить seed; существующие ответы и паспорта не перезаписываются |
| `make pipeline` | Отдельно собрать открытые данные и пересчитать географические характеристики |
| `make eval` | Пересчитать отчёт по сохранённым данным и слабым меткам |
| `make test` / `make lint` | Тесты / Python и frontend lint |
| `make coverage` | Тесты с покрытием backend/geo, JSON в `docs/checks/coverage.json` |
| `make demo-check` | Приёмка Маши, пяти персон, доказательств и synthetic provenance |
| `make smoke` | Проверка работающего стенда и затем demo-check |
| `make audit` | Четыре Python и три npm скана зависимостей |
| `make check` | Lint, тесты, аудит и smoke уже запущенного Compose |
| `make demo-video` | Записать скринкаст по сценарию |
| `make demo-voice VOICE=/path/to/voice.wav` | Добавить голос владельца в отдельный MP4 без перекодирования видео |

Миграции запускает `backend.boot` при старте контейнера. Не запускайте `python -m backend.boot` внутри уже работающего app: он попытается поднять второй HTTP-сервер. Для повторной загрузки данных используйте `make seed`.

После изменений: `make lint`, `make test`, `docker compose up --build -d`, `make smoke`. Проверяйте отсутствие файлов больше 50 МБ, tracked `.env` и реальных токенов в diff и истории. Все зафиксированные результаты и открытые пункты ведутся в `docs/STATUS.md`; перед сдачей сверяйте их с отчётами `docs/checks/` и аудитом `docs/audits/summary.json`.

Контрольная точка сборки 26.10.2026: образ `linux/amd64` занимает 315 513 186 байт (около 301 MiB), старт с пустой БД и готовым образом проверен за 46 с. После security-интеграции прошли 365 тестов и 125 subtests; покрытие строк Python — 85% (4 597 / 5 413, каталоги тестов исключены), отчёт [coverage.json](checks/coverage.json). Полный pytest, lint, сборка интерфейса и аудит повторяются после интеграций; актуальные результаты с SHA находятся в [STATUS](STATUS.md), результаты четырёх Python и трёх npm сканов — в `docs/audits/summary.json`.

Чистый клон snapshot `3e3cc92`, пустой кэш builder, новая БД и `docker compose up --build`: health через 139,49 с, полный прогон — 212,29 с, browser preview прошёл. `.env` был скопирован из примера; отдельный запуск без `.env` ещё проверяется. Результат относится к этому snapshot, а не автоматически к последующим изменениям. Startup не является временем pipeline.

Второй регион проверен изолированно: 30 объектов Геленджика, 14 стадий за 19,02 мин с cached PBF и готовым образом, compute 373,25 с одним worker. Измеренный lifetime RSS процесса около 1,81 ГБ не является пиком контейнера или каждой стадии. Условная оценка того же состава 1000 hotel calls — 3,28 ч по среднему, 4,84 ч по p90 плюс подготовка/холодные загрузки/валидация/кэши; реального прогона 1000 объектов не было. Полный pipeline Сочи по стадиям ещё не измерен. Параметры, ресурсы, команды изоляции и границы переноса — в [region_gelendzhik.md](checks/region_gelendzhik.md). Для нового региона нужны подходящая проекция, явный terrain bbox/DEM и корректный cache hotel ID; текущие defaults не являются глобальной автоматизацией.

## Данные

Исходники загружаются в исключённую из Git директорию `data/raw/`. Сборка приложения не запускает pipeline. Лицензии, даты и SHA-256 открытых выгрузок находятся в `data/seed/manifest.json`, `data/seed/sources.json` и на `/sources`. Контракты seed — в `docs/CONTRACTS.md` §3, сценарии и ограничения синтетических данных — в `docs/internal/DEMO_FIXTURES.md`. Реальные фото сопровождаются лицензиями конкретных файлов. OTA не используются.

40 слабых меток сайтов относятся к 40 объектам, четыре метки парковки ограничены по смыслу. Независимых ручных меток нет; nDCG и полевая точность не измерены. Синтетические сценарии не считаются реальным покрытием или подтверждениями гостиниц.

Сбор сайтов — отдельный разовый этап подготовки с robots.txt и запретом OTA. Runtime читает сохранённые фрагменты, сетевого website fetch нет. `python -m scripts.compare_filters` воспроизводит модельное сравнение с береговым фильтром; результат `data/eval/filter_baseline.json` и методику нужно читать вместе. Поле `provenance` в `GET /api/quality` использует единицу materialized facts, а не отели; mixed входит в synthetic, неизвестные/устаревшие/спорные значения исключены из знаменателя доли. Чистый seed-отчёт `data/eval/results.json`: 23 744 известных значения, 10 synthetic (≈0,0421%), включая 3 mixed; это не доля runtime после демонстрации.

## Диагностика

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 db
curl -f http://localhost:8080/health
```

Не удаляйте volumes при обычной остановке: там находятся ответы, паспорта и результаты пересчётов. Для намеренного полного сброса демо используйте `docker compose down -v`; все локальные изменения будут потеряны.

При поездке позже срока действия доказательств паспорт показывает необходимость перепроверки. Подтверждение номера не превращает текущие данные в гарантию будущих условий. Сначала проверьте даты поездки, срок доказательств, ограничения фасада и этажа, а затем таймлайн паспорта.

## Видео и сдача

Для записи нужны Node.js 22+, Chrome/Chromium и системные `ffmpeg`/`ffprobe`. Зависимости записи закреплены в `demo/package-lock.json`; `make demo-video` устанавливает npm-зависимости и Chromium, затем запускает сценарий. Подробности и параметры — в `demo/SCRIPT.md`.

Скринкаст готов: около 3 минут (178,9 с), 1920×1080, 30 кадров/с, около 10 МБ. Пройдены 11 сцен без ошибок, заполнение новой характеристики завершено для всех 250 отелей. Локальный файл `demo/okno-demo.mp4` не коммитится. Владелец должен предоставить публичную ссылку для README; доступ к ней проверяется в инкогнито.

Базовый MP4 содержит титры и не содержит звуковой дорожки. Для записи голоса подготовлен [demo/VOICEOVER.md](../demo/VOICEOVER.md). Команда `make demo-voice VOICE=/path/to/voice.wav` создаёт `demo/okno-demo-voiced.mp4`, сохраняя исходник и видеопоток; слишком длинная дорожка отклоняется. Наличие текста и helper не означает, что голос уже записан.

Перед финальным тегом нужен чистый клон и пустой кэш сборки: замерить `docker compose up --build`, пройти smoke и ручной сценарий. Фактическое время, размер образа, SHA и результаты записать в STATUS и README. Не подменять этот замер стартом с готовым образом или существующей БД.

Текущий origin: `https://github.com/shttrkk/okoshko.git` — личный репозиторий, не адрес сдачи по правилам. URL команды в `ostrovok-hackathon-2026` указывает владелец. Тег `submission` ставится на последний коммит main после финального прогона. Push main и тега выполняет только владелец самостоятельно; оркестратор не вызывает `git push` и не меняет публичность репозитория. После отправки владелец сверяет удалённые SHA main и submission с проверенным локальным коммитом. Сдача не считается выполненной до проверки удалённого тега и публичной ссылки на видео.

Полная история коммитов сохраняется при переносе в репозиторий команды. История и refs не переписываются ради размера: squash, filter-repo, orphan-ветки и копия дерева с новым корневым коммитом не используются. Цель размера pack носит рекомендательный характер и не отменяет сохранение истории.

Ссылки на публичное видео и репозиторий команды отложены владельцем до полной готовности; placeholders остаются до его сообщения. Техническое устройство — в [ARCHITECTURE](ARCHITECTURE.md), модель продукта — в [PRODUCT](PRODUCT.md), контракты — в [CONTRACTS](CONTRACTS.md).
