# Проверенные фотографии отелей и номеров

Индекс: `data/seed/hotel_photos.json`; решения по конкретным URL: `data/eval/hotel_photos_review.json`. Фотография не доказывает вид из окна, этаж, сторону, наличие свободного номера или текущее состояние здания.

## Формат и порядок показа

| kind | Назначение | Хранение | Атрибуция |
|---|---|---|---|
| `building` | Само здание, Wikimedia Commons | Локальный WebP до 800 px и 150 КБ | Автор, свободная лицензия и страница файла |
| `official_site` | Фото с собственного сайта отеля: здание, территория или интерьер | Только URL изображения и страницы на домене seed.website | «Фото с сайта отеля»; author/license/license_url=null |
| `street` | Узнаваемое здание с улицы, Mapillary | Локальный WebP до 640 px и 60000 Б | «Вид с улицы · Mapillary · автор, год», CC BY-SA 4.0, ссылка на кадр |
| `room` | Интерьер гостевого номера, до 8 на отель | Только URL изображения и страницы на домене seed.website | «С сайта отеля · ваш номер может отличаться» |

Обложка: building → official_site → street → схема района. Room не становится обложкой. Для отеля без обложки карточка показывает внешнюю ссылку на поиск фото и отзывов на Яндекс Картах; на странице отеля эта ссылка есть всегда. Это поиск названия около переданных координат, а не обещание открыть однозначную карточку организации. Виджет поиска не встраивается.

Интерьер допускается как official_site обложка с соответствующей подписью, но тот же URL не повторяется в room: иначе изображение галереи загрузилось бы до её открытия. Число фото номеров учитывается отдельно от покрытия обложек. Схема и фото различаются, © OpenStreetMap contributors сохранено.

Строгий контракт seed/API: HotelPhoto и HotelPhotoIndex в `docs/schemas.json`; `GET /api/hotels/{id}/photos` описан в `docs/openapi.json`. Старый статический индекс остаётся совместимым. У каждой принятой записи verified_by_eye=true. Локальные файлы имеют bytes и SHA-256; у street обязательны автор, год, image_id, лицензия и ссылка на кадр. Токены в ссылках запрещены.

## Получение и проверка

- Источник сайтов — только seed.website. Проверяются название и местоположение отеля. Проданные домены, чужие объекты, общесетевые страницы без однозначного объекта и отели вне региона исключаются.
- Используются реальные ссылки из HTML на галерею, номера и описание отеля. Bounded-проход: до трёх страниц и до восьми новых изображений на источник; уже принятые URL и их страницы учитываются отдельно для воспроизводимости. Ссылки на оптимизатор изображений собственного сайта допустимы только если уже присутствуют в его HTML; искусственные proxy URL не создаются.
- До каждого сетевого запроса и после смены origin проверяется robots.txt. Частота ≤1 запрос/с на хост; для публичных API Wikimedia сохранены ограничения сборщика. Запреты, TLS-ошибки, недоступность и антибот-защита не обходятся.
- Яндекс, 2ГИС, Google, OTA, их фото-CDN и соцсети не служат источниками. Никакие их ключи или API не используются. Официальные изображения и страницы должны оставаться на домене сайта отеля, включая редиректы. Ранее разрешённые внешние CDN больше не являются исключением.
- Каждая принятая фотография просмотрена глазами. Отклоняются логотипы, баннеры, рендеры, посторонние объекты, рекламные сюжеты и неопределённые общесетевые кадры. Для room дополнительно исключаются лобби, рестораны, коридоры, вид без спальни и контентные дубли. Неизвестная принадлежность не превращается в положительное решение.
- Новые оригиналы official_site/room не записываются на диск и не попадают в git или образ: после проверки в памяти сохраняются только метаданные и маленькие игнорируемые QA-превью/контактные листы для просмотра. Их задача — проверка, а не показ в продукте. Старый raw-кэш не переписывается.
- Фото галереи создаются в DOM только после нажатия кнопки. Если все изображения недоступны, остаются сообщение и ссылка на сайт отеля. До действия гостя нет запросов к Яндексу/Mapillary и к URL галереи; совпадение URL галереи и обложки запрещено.

## Сборка и воспроизводимость

Pillow 13.0.0 закреплён с хешами в requirements-dev.lock. Он нужен только для подготовки и проверки данных, в образ приложения не добавляется.

```sh
.venv/bin/python -m pip install --only-binary=:all: --require-hashes -r requirements-dev.lock
.venv/bin/python -m scripts.collect_hotel_photos --expand-official --skip-commons --require-review
.venv/bin/python -m scripts.collect_hotel_photos --expand-official --skip-commons --offline --require-review
.venv/bin/python -m pytest -q tests/test_hotel_photos.py tests/test_photo_collection.py tests/test_photo_contracts.py
```

`--skip-commons` сохраняет уже проверенные building-записи, `--only` не удаляет остальные отели. Сборщик не одобряет изображения автоматически: после просмотра точные URL заносятся в review и повторяется сборка с --require-review. Для воспроизведения этой сессии используются игнорируемые `data/raw/hotel_photos_extended` и read-only fallback `data/raw/hotel_photos`: добавьте `--cache-dir data/raw/hotel_photos_extended --read-cache-dir data/raw/hotel_photos`. Чистая offline-сборка linked-записей с пустым output воспроизвела все 122 сочетания (hotel_id, kind, URL), сетевых запросов 0. Raw-кэш не нужен для запуска продукта: принятый индекс и свободные миниатюры уже в репозитории.
