# О!кно: сценарий записи и озвучки

Готовая озвучка владельцем для итогового ролика 178,9 с: [VOICEOVER.md](VOICEOVER.md), 381 слово и 11 сцен с таймкодами. Таблица ниже описывает исходный план сцен; для записи голоса используйте таймкоды VOICEOVER. Сведение отдельного output выполняет `python -m scripts.mix_voice --voice ... --video demo/okno-demo.mp4 --output demo/okno-demo-voiced.mp4`.

Видео показывает настоящее приложение на `http://localhost:8080`. Ответы API не подменяются. Персона Маша, номер комнаты и бронирование — демонстрационные. Три ответа о тишине, ответ симулятора отельера и новый дом явно помечены как синтетические. Геометрия, маршрут и солнечный путь берутся из сохранённых расчётов по открытым данным.

## Запуск

Нужны запущенный Docker Compose стенд, Node.js 22+, уже установленный Chrome/Chromium и `ffmpeg`/`ffprobe` в PATH. Сборка приложения и установка зависимостей демо выполняются отдельно. Скрипт не скачивает браузеры или ffmpeg и не обращается к внешним сервисам. Если ffmpeg ещё не зарегистрирован в кеше Playwright, создаётся ссылка на уже установленный системный бинарный файл. Для установленного macOS Chrome исправляется размер окна screencast, чтобы нижние титры попадали в видео полностью.

```sh
cd demo
npm ci
npm run check
npm run audit
npm run preview
npm run record
```

`preview` проходит UI без записи, публикации новой характеристики и симуляции здания. Он создаёт предварительный учебный паспорт без дат, запускает агента и подтверждает явно синтетический ответ — это интеграционная проверка, а не read-only режим.

Переменные окружения:

- `OKNO_BASE_URL` — адрес приложения, по умолчанию `http://localhost:8080`.
- `OKNO_BROWSER_EXECUTABLE` — путь к уже установленному Chrome/Chromium; стандартный путь macOS и распространённые Linux пути определяются автоматически.
- `OKNO_HEADLESS=false` — показать окно браузера.
- `OKNO_DEMO_OUTPUT` — путь MP4 относительно корня проекта, по умолчанию `demo/okno-demo.mp4`.
- `OKNO_DEMO_HOTEL` — необязательный ID одного из трёх подходящих отелей; без него выбирается первый результат живого поиска.

Перед записью нужна свежая локальная БД без уже применённого события нового дома у выбранного отеля. Скрипт никогда не удаляет данные. `changes/simulate` идемпотентен: повторное событие не может честно уведомить только что созданный паспорт. Для нового дубля сначала восстановите чистый стенд штатным способом, согласованным с владельцем окружения. Во время записи не пересобирайте контейнер: это завершает демонстрационную auth-сессию.

Видео записывается через Playwright BrowserContext с размером **1920 × 1080**. Приложение занимает верхние 968 пикселей, отдельная нижняя полоса — титры. Она не перекрывает синтетические метки и факты. Скрипт не внедряет титры в продуктовые файлы. Локальная recording-оболочка `/__okno-recording__` создаётся только в браузерном контексте записи; единственный `route.fulfill` обслуживает эту оболочку. API, бизнес-данные и ответы приложения не подменяются.

Результаты:

- `demo/okno-demo.mp4` — H.264, не более 180 секунд, без аудиодорожки; русские титры встроены в запись.
- `demo/recordings/<timestamp>/okno-demo-source.webm` — исходная запись, резервный видеофайл.
- `demo/recordings/<timestamp>/report.json` — фактические API ID, длительность сцен, browser errors и результаты проверок.
- PNG в том же каталоге — кадры для визуальной проверки.

Видео и записи исключены из git. Ничего не загружается и не публикуется автоматически. Для человеческой озвучки используйте текст ниже. Фактические названия отеля, этаж и значения берутся из UI, а не из примерных чисел blueprint.

## Что проверяет запись

- Живой поиск возвращает не менее трёх all-результатов с явной synthetic-маркировкой тишины.
- Отель оценивается с текущим ParsedQuery; сравнение получает те же условия.
- Существуют реальные фасады, пешеходный маршрут и профиль горизонта; карта загружает локальные PMTiles.
- Предпросмотр ответа синтетический, цитаты входят в raw_text, confirm создаёт claims.
- Даты паспорта явно очищаются через UI; это предварительный выбор, а не обход срока актуальности. Паспорт подтверждён менеджером и затем действительно получает уведомление о новом доме. Датированная поездка за пределами TTL должна оставаться at_risk до перепроверки.
- `morning_swim` проходит compile/dry-run, публикуется и появляется чипом поиска. Неизвестные входы остаются неизвестными.
- У агента видны реальные SSE шаги.
- В браузере нет uncaught errors и ответов API/assets со статусом 4xx/5xx; внешние запросы блокируются и считаются ошибкой записи.
