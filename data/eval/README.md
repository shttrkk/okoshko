# Методика оценки О!кно

Цель — проверить соответствие ожиданий гостя характеристикам конкретного номера/фасада/этажа, не выдать устойчивость расчёта за реальную точность.

## Наборы

1. **manual**: независимая ручная проверка по фото с понятным направлением/высотой, официальным описаниям категории номера и геометрии реального маршрута. Стратифицированная цель — 40–60 отелей (первая линия, застройка перед морем, холмы, железная дорога, тихий двор). 20% меток желательно проверить вторым человеком. Этаж, фасад и месяц фиксируются в scope.
2. **weak_website**: дословные цитаты только с официальных сайтов отелей; URL, дата, quote и сохранённый разрешённый фрагмент обязательны. Сайт может ошибаться и описывать часть номеров, поэтому это слабая метка. Цитата «есть номера с видом на море» не означает, что все номера видовые.
3. **synthetic_parser**: созданные вручную примеры ответов имитатора с эталонными полями и цитатами. Это тест способности парсера, не точность данных реальных отелей. Отчёт отдельный.
4. **search_judgments**: независимые оценки релевантности 0/1/2 для запросов персон, pooling top-10 системы и baseline. nDCG@5 публикуется только когда есть такие оценки. Отсутствие разметки не заменяется сортировкой по собственному скору системы.

## Файл labels.csv

`id,hotel_id,characteristic_id,scope,value,label_type,evidence_url,quote,labeler,observed_at`.
`scope` и `value` — JSON. Метка available=true/false ставится только при достаточном доказательстве. Unknown остаётся пропуском. Отрицательная метка «море не видно» требует проверки конкретного scope; отсутствие рекламного утверждения не является отрицательной меткой.

Пример (синтаксис, не ground truth): `scope={"facade":"W","floor_min":5}`, `value={"available":true}`.

## Текущий curated website набор

В `labels.csv` **40 weak_website меток для 40 разных объектов**, включая **4 частичные метки наличия парковки**. Независимой ручной / полевой разметки (`manual`) — **0**. Состав: sea_view 22, pets 5, soundproofing 1, beach_walk 6, car_access 4, room_orientation 2. Исходные 20 одобренных меток сохранены.

`curation.json` фиксирует accepted IDs, scope/value, критерии поддержки цитатой, batch/index кандидата и причины исключения. Причины исключения не публикуют отклонённые цитаты. Два ID Dolphin с одним официальным сайтом и одной цитатой считаются одним реальным отелем; дополнительный Overture ID исключён. Описание балкона из девелоперского проекта Benefit не принято как существующая категория бронируемого номера.

- Цитата про вид подтверждает только заявленное существование видовых номеров. Общий текст не назначается всем фасадам, этажам и категориям.
- Пляжные цитаты подтверждают заявленную близость / доступ к морю. `quoted_distance` сохраняет число и отношение из текста; «меньше 600 метров» у Fidan — `less_than`, а не точные 600 м. `minutes` и `return_minutes` остаются null; геометрия, уклон, переходы и пешее время из текста не выводятся.
- Парковка: `parking_available=true`, **`available=null`**. Это 4 частичные field labels, не доказательство подъезда автомобиля ко входу или доступного парковочного места. Они не участвуют в бинарной accuracy по car_access.available.
- Балкон привязан к точной процитированной категории `Двухместный номер с балконом`; фасад / этаж неизвестны, остальные категории не наследуют значение.
- Разрешение питомцев «по запросу» сохраняет необходимость согласования. Виды животных, масса и цена остаются неизвестными без прямого подтверждения.
- Claim source `hotel_website`, confidence 0.55, TTL 180 дней от даты сохранённого batch. Это слабое заявление сайта, не реальный ответ отельера и не независимое измерение.

Публичный evidence содержит один одобренный дословный фрагмент на URL, максимум 25 слов суммарно на страницу. Полные HTML/text, автоматические candidate CSV и отклонённые excerpts находятся только в gitignored `data/raw/`; они не входят в ground truth. Fetch log сохраняет оба сбора: initial 100 сайтов и extra 66 сайтов, всего 206 записей запросов; это число попыток сбора, не число независимых ground-truth объектов.

Воспроизведение экспорта и проверка связей не требуют сети:

```sh
.venv/bin/python -m scripts.collect_weak_labels --curate data/eval/curation.json
.venv/bin/python -m scripts.collect_weak_labels --validate-curation data/eval/curation.json
```

При наличии локального raw cache точная цитата и исходный HTML SHA-256 дополнительно проверяются строго:

```sh
.venv/bin/python -m scripts.collect_weak_labels --validate-curation data/eval/curation.json --require-raw
```

Новый сетевой сбор создаёт **только неразмеченные кандидаты** в gitignored каталоге; он не перезаписывает curated labels. Данные сайтов могут измениться, поэтому новый сбор не обещает старый HTML hash. Для принятия нужны проверка identity, room context, точного фрагмента и ручное решение в curation manifest. Collector проверяет robots.txt до страницы и заново для origin после редиректа, блокирует OTA, не создаёт отрицательные метки из отсутствия текста; общие заголовки услуг и сомнительные совпадения требуют отклонения на review.

```sh
.venv/bin/python -m scripts.collect_weak_labels --hotels data/seed/hotels.json \
  --max-hotels 100 --output-dir data/raw/website_candidates/new_batch
```

## Метрики

- Отдельно для каждого типа разметки и характеристики: accuracy, precision, recall, F1, abstentions.
- Coverage = пары отель×характеристика с известным текущим фактом / все активные пары. Фасадные значения не умножают знаменатель искусственно.
- Confidence — надёжность выбранного значения. Для Brier/ECE вероятность положительного класса = c при available=true, 1−c при false. Выводим калибровочные bins и selective accuracy при порогах 0.5–0.9.
- Ответы отельера: field-level exact match и проверка quote in raw_text; отдельно ясные, расплывчатые и противоречивые ответы.
- Search: nDCG@5 на независимых relevance judgments, доля выполненных обязательных условий и parse F1 по 25+ русским запросам.
- Неизмеренная метрика — null и «ещё не измерено» в UI. Ноль используется только как реально измеренное значение.
- Совпадение с weak_website — согласие с короткой цитатой сайта, не полевая точность вида, маршрута, парковки или балкона. Brier/ECE на таком наборе не являются эмпирической калибровкой модели на проверенных отелях. nDCG@5 и полевая accuracy не публикуются как измеренные без соответствующей независимой разметки.

`make eval` читает версионированный seed и сохраняет `results.json`. `/api/quality` дополнительно учитывает сохранённые в БД ручные метки. Версию коммита и дату запуска записываем при финальной оценке. Метки из `/quality/label` сохраняются, повторный запуск контейнера их не перезаписывает.
